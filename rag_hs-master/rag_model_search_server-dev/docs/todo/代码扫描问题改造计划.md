**策略**：
- 同一文件内重复 ≥ 3 次的字面量提取为常量；

### 10.2 改造模式说明

**T1 raise-missing-from（48 条）**：
- 模式 A：`except X:` → `except X as e:` + `raise Y(...) from e`
- 模式 B：`except X as e: raise Y(...)` → 加 `from e`
- 模式 C：`except X as e:` 内层已有局部捕获变量时，使用 `from <local_var>` 链到底层异常
- 模式 D：except 块内无 `as` 变量且底层异常不携带有用信息时，使用 `from None` 显式抑制链

**T2 bare-except（12 条）**：
- 能识别具体异常：`except:` → `except OSError:` / `except (ImportError, AttributeError):` / `except (TypeError, ValueError):` / `except (ZeroDivisionError, TypeError):`
- 不能识别：`except:` → `except Exception:`（如 COM Dispatch、numexpr 启动、TextSplitter fallback、torch.cuda 检测）

**T3 broad-exception-raised（15 条）**：
- `raise Exception(...)` → `raise RuntimeError(...)`（通用运行时错误）
- `raise Exception("Word转PDF超时...")` → `raise TimeoutError(...) from None`
- `raise Exception("未找到LibreOffice...")` → `raise FileNotFoundError(...) from None`
- 均为 Exception 子类，调用方 `except Exception` 不受影响

**T4 try-except-raise / no-else-raise（3 条）**：
- 删除无意义的 `try: ... except (Exception, asyncio.CancelledError): raise` 包裹（行为等价，CancelledError 自然向上传播）
- `elif isinstance(cache, X):` → `if isinstance(cache, X):`（前一分支已 raise，避免不必要 elif）

**T5 broad-exception-caught（239 条）Makefile 项目级豁免**：
- 239 条样本分析：业务 209 + 测试 30，分布于 72 个文件
- 热点：FastAPI handler 兜底 500（kb_doc_api.py 29）、外部 API 调用（kafka_producer.py 11、memmachine_client.py 10）、批处理 fail-open（processing_engine.py 10）、测试 fixture/teardown 容错（30 条）
- 决策：参考 B5 protected-access 模式，Makefile `lint` / `lint-tests` / `lint-baseline` 三个 target 统一加入 `--disable=broad-exception-caught`
- 理由：broad-exception-caught 为风格规则而非正确性规则，pylint 官方文档建议项目级豁免；逐条改造代价高且多数为合法防御性编程；T1-T4 已完成 78 条真正改善
