
# MemMachine 代码风格指南

代码风格的一致性对于可读性和协作至关重要。本指南概述了对 MemMachine 项目所有贡献的核心原则，并指出了针对每种语言的特定自动化风格强制工具。

## 核心原则

- **可读性：** 代码应易于阅读和理解。优先选择清晰而非取巧。
- **一致性：** 遵循周围代码的既定风格和格式。如有疑问，请遵循本指南的建议。
- **清晰性：** 为变量、函数和类使用有意义的名称。除非是标准且广泛理解的缩写，否则应避免使用缩写。
- **文档化：** 所有公共 API、复杂函数和非显而易见的代码段都应有完善的注释。

## 语言专属风格指南与工具

我们使用自动化工具来强制执行风格指南。请在提交 pull request 之前安装并运行这些工具。
它们可以作为 `dev` 组的一部分通过 `uv sync` 轻松安装。

### Python
- **格式化工具：** [**Ruff**](https://github.com/astral-sh/ruff)
  - Ruff 是一个极快的代码格式化工具，可自动格式化 Python 代码。
- **Linter：** [**Ruff**](https://github.com/astral-sh/ruff)
  - Ruff 是一个极快的 linter，旨在作为 flake8 和 isort 等工具的直接替代品。它能捕获常见的 bug 和风格问题。
- **类型检查器：** [**ty**](https://github.com/astral-sh/ty)
  - ty 是一个 Python 静态类型检查器。

### Markdown

- **风格指南：** 我们对 Markdown 文件遵循一致的风格，以确保文档易于阅读和维护。
  - **行长：** 将行限制为 80 个字符以提高可读性，尤其是在查看 diff 时。
    - **标题：** 使用 `#` 作为顶级标题，使用 `##`、`###` 等作为子标题。
    - **代码块：** 对所有代码块使用三个反引号（```）并附带语言标识符（例如 `python`、`javascript`）。
    - **强调：** 使用单个星号（`*`）表示斜体，双星号（`**`）表示粗体。
    - **链接：** 使用有意义、描述性的链接文本，而不是"点击这里"。
    - **列表：** 使用连字符（`-`）表示无序列表，使用一致的编号表示有序列表。
- **Linter：** [**markdownlint**](https://github.com/DavidAnson/markdownlint)
  - 使用 markdownlint 检查 Markdown 文件中的风格和格式问题。

## 格式化

- **自动格式化：** 我们使用自动化工具来格式化代码。请在提交前运行格式化工具（例如对 Python 使用 Ruff），以确保所有代码的风格正确。
- **Lint 检查：** 我们的 CI 流水线在每个 pull request 上都会运行 linter（例如 Ruff 或 ESLint）。你的更改必须通过这些检查才能被合并。
- **编辑器配置：** 我们强烈建议配置你的编辑器（例如 VS Code）并安装相应的扩展，以便在保存时自动格式化和 lint 代码。这使得遵循风格指南变得毫不费力。
