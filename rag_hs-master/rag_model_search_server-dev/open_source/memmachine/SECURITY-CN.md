
# 安全策略

MemMachine 团队非常重视我们项目及其用户的安全。我们感谢安全研究人员及其他致力于负责任地披露漏洞的人员所付出的努力。

## 报告漏洞

我们已为该仓库启用 GitHub 的私密漏洞报告功能。这是报告安全漏洞的首选方法。

**请勿创建公开的 GitHub issue。** 公开披露漏洞可能会给社区带来风险。

要报告漏洞，请访问我们仓库的
[Security 标签页](https://github.com/MemMachine/MemMachine/security)，并点击"Report a privately reported vulnerability"。我们将在 2 个工作日内确认收到您的报告，并与您一起了解问题、协调解决方案。

## 报告指南

为帮助我们更有效、更快速地处理漏洞，请在报告中包含以下信息：

- **描述：** 漏洞的清晰简洁描述。
- **复现步骤：** 可用于演示该漏洞的最小可复现代码片段或步骤。
- **环境：** 操作系统、库版本，以及任何其他相关细节。
- **预期行为：** 在没有漏洞的情况下，您预期发生的行为描述。

### 支持的版本

我们致力于为 MemMachine 的最新稳定版本提供安全更新。

- **最新主版本（例如 v1.x.y）：** 我们将为该版本中的任何安全漏洞提供安全补丁和修复。
- **以往的主版本：** 我们不会为旧版本提供安全补丁。请升级到最新版本以确保您受到保护。

## 公开披露

我们相信协调的、负责任的披露。漏洞报告后，我们将致力于验证并修复该问题。然后，我们将在公开的 GitHub Security Advisory 中公布该漏洞及其修复情况，并给予报告者署名，除非报告者希望保持匿名。我们请求报告者在修复发布之前，不要公开披露该漏洞。
