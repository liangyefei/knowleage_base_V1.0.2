
# MemMachine 项目治理

本文档概述了 MemMachine 项目的治理模型，该项目是一个由社区驱动的开源倡议。我们的目标是创建一个透明、任人唯贤且协作的环境，让每一位贡献者都能增长其影响力并塑造项目的未来。

## 1. 项目理念

MemMachine 项目采用任人唯贤的模型运作。所有参与者都因其贡献而受到认可，在项目中的影响力则是通过与社区积极、持续且有意义的参与而获得。

## 2. 角色与职责

项目认可若干不同的角色，每个角色都具有递增的责任与信任级别。

### 用户

- **定义：** 使用项目软件的社区成员。
- **职责：** 提供反馈、报告缺陷并参与讨论。

#### 贡献者

- **定义：** 对项目做出直接贡献的用户，例如提交缺陷报告、为新功能创建拉取请求或改进文档。
- **职责：** 遵守项目的行为准则、风格指南和贡献指南。

#### 维护者

- **定义：** 展现出高度投入、专业能力以及积极社区参与的长期贡献者。维护者被授予对仓库的 **写权限**。
- **职责：**
  - 审查并合并拉取请求。
  - 对问题进行分类与管理。
  - 指导新贡献者。
  - 参与项目讨论和决策。

#### 技术委员会

- **定义：** 从维护者团队中选出的一小群人。技术委员会为整个项目提供战略和技术上的监督。
- **职责：**
  - 制定项目的战略路线图。
  - 指导维护者团队。
  - 执行行为准则。
  - 担任项目的对外代表。

### 3. 决策流程

MemMachine 项目内的决策通过 **惰性共识** 作出，这是一种在特定时间范围内若无人反对则视为决策已获批准的流程。对于任何提案或变更，投票将持续 72 小时。

- 若未提出异议，则提案被视为通过。
- 若提出强烈异议，将举行公开讨论以寻找前进方向。
- 若无法达成共识，项目负责人将作出最终决定。

### 4. 如何成为维护者

成为维护者基于在社区中展现出的功绩与信任。成为维护者的路径如下：

1. **持续贡献：** 在数月期间持续贡献高质量的代码、文档或其他有价值的工作。

2. **社区参与：** 积极参与问题、讨论和代码审查，展现出积极且乐于助人的态度。

3. **提名：** 一位现有维护者或项目负责人将提名你担任该角色。

4. **投票：** 现有维护者团队将对提名进行投票。需获得多数票通过。

### 5. 冲突解决与行为准则

MemMachine 社区的所有成员都应遵循[行为准则](https://www.google.com/search?q=CODE_OF_CONDUCT.md)。所有问题或冲突都应以专业和尊重的方式解决，如行为准则的举报指南所述。
