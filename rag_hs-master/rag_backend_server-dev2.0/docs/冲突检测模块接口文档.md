# 冲突检测模块接口文档

> 前缀：`/hisilicon-knowledge/kb/conflicts`
> 认证：所有接口需 JWT（Header `Authorization: Bearer <token>`）
> 统一返回外壳：`{ "code": "0", "data": {...}, "message": "操作成功" }`
> 分页返回结构：`{ "pageNumber": 1, "pageSize": 20, "totalPage": 1, "totalRow": 2, "records": [...] }`

---

## 1. 查自动检测开关状态

**GET** `/kb/conflicts/settings/auto-detection`

### 示例

```
GET http://localhost:8080/hisilicon-knowledge/kb/conflicts/settings/auto-detection
Authorization: Bearer <token>
Accept-Language: zh-CN
```

### 响应

```json
{
  "code": "0",
  "data": {
    "enabled": false,
    "updatedAt": null
  },
  "message": "操作成功"
}
```

---

## 2. 切换自动检测开关

**POST** `/kb/conflicts/settings/auto-detection`

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| enabled | boolean | 是 | true=开启 / false=关闭 |

### 示例

```
POST http://localhost:8080/hisilicon-knowledge/kb/conflicts/settings/auto-detection
Authorization: Bearer <token>
Content-Type: application/json
Accept-Language: zh-CN

{
  "enabled": true
}
```

### 响应

```json
{
  "code": "0",
  "data": {
    "enabled": true,
    "updatedAt": "2026-10-16 15:30:00"
  },
  "message": "操作成功"
}
```

## 3. 发起手动扫描（立即检测）

**POST** `/kb/conflicts/start-scan`

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| nodes | array | 是 | 勾选范围节点列表，至少 1 条 |
| nodes[].kbId | string | 是 | 知识库 ID |
| nodes[].categoryId | string | 否 | 目录 ID，不传=整库 |

### 示例

```
POST http://localhost:8080/hisilicon-knowledge/kb/conflicts/start-scan
Authorization: Bearer <token>
Content-Type: application/json
Accept-Language: zh-CN

{
  "nodes": [
    { "kbId": "kb-diting" }
  ]
}
```

### 响应

```json
{
  "code": "0",
  "data": {
    "jobId": "cj3f8a2b1c4d5e6f7a8b9c0d1e2f3a4b",
    "batchNo": "CHK-20261016-01",
    "totalDocuments": 2
  },
  "message": "操作成功"
}
```

### 可能的错误码

| code | 说明 |
|---|---|
| A0448 | 所选范围内没有可检测的已发布知识片段 |
| A0449 | 该范围已有检测任务进行中 |
| A0425 | 所选范围文档数超出上限（默认 2000） |
| C0001 | 模型服务调用失败（remote 模式） |

## 4. 轮询任务进度

**GET** `/kb/conflicts/jobs/{jobId}`

### 示例

```
GET http://localhost:8080/hisilicon-knowledge/kb/conflicts/jobs/cj3f8a2b1c4d5e6f7a8b9c0d1e2f3a4b
Authorization: Bearer <token>
Accept-Language: zh-CN
```

### 响应

```json
{
  "code": "0",
  "data": {
    "jobId": "cj3f8a2b1c4d5e6f7a8b9c0d1e2f3a4b",
    "batchNo": "CHK-20261016-01",
    "status": "RUNNING",
    "totalDocuments": 2,
    "scannedChunks": 0,
    "newConflictCount": 0,
    "hitConflictCount": 0,
    "failedItems": 0,
    "error": null
  },
  "message": "操作成功"
}
```

### status 枚举

`QUEUED` → `RUNNING` → `COMPLETED` / `PARTIAL` / `FAILED` / `ABORTED`

前端轮询到终态（COMPLETED/PARTIAL/FAILED）后刷新冲突列表。

> **注意**：当前 `client-mode=stub`，job 停在 RUNNING 不会自动完成，需要手动模拟回调。

## 5. 分页查询冲突列表

**GET** `/kb/conflicts`

### Query 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| keyword | string | 否 | 冲突主题模糊搜索 |
| type | string | 否 | FACT / SEMANTIC / VERSION / CROSS_MODAL / NEAR_DUPLICATE |
| kbId | string | 否 | 按知识库过滤 |
| badcaseSubmitted | boolean | 否 | true=已提交 badcase / false=未提交 / 不传=全部 |
| page | int | 否 | 页码，默认 1 |
| pageSize | int | 否 | 每页条数，默认 20，最大 100 |

```
GET http://localhost:8080/hisilicon-knowledge/kb/conflicts?badcaseSubmitted=false&page=1&pageSize=20
```

## 7. 提交 Badcase 工单

**POST** `/kb/conflicts/{id}/badcase`

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| description | string | 是 | 问题描述，1~1000 字 |

> 冲突 ID 从 URL 路径传入，body 里不需要再传 recordId。

### 示例

```
POST http://localhost:8080/hisilicon-knowledge/kb/conflicts/cr-diting-uart-001/badcase
Authorization: Bearer <token>
Content-Type: application/json
Accept-Language: zh-CN

{
  "description": "冲突判定与实际情况不符，3Mbps 为早期工程样片参数，非现售规格。"
}
```

### 响应

```json
{
  "code": "0",
  "data": {
    "ticketId": "ct1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c"
  },
  "message": "操作成功"
}
```

### 可能的错误码

| code | 说明 |
|---|---|
| A0444 | 冲突记录不存在 |
| A0447 | 该冲突已提交 Badcase 工单，请勿重复提交 |

## Postman 测试顺序建议

1. 先跑示例数据 SQL（`migration_019_conflict_detection_sample_data.sql`），让库里有数据
2. **GET** `/settings/auto-detection` → 确认开关状态
3. **POST** `/settings/auto-detection` `{enabled: true}` → 打开自动检测
4. **POST** `/start-scan` → 发起手动扫描（stub 模式下 job 立即置 RUNNING）
5. **GET** `/jobs/{jobId}` → 轮询任务状态
6. **GET** `/conflicts` → 查冲突列表（可用 `badcaseSubmitted=false` 筛选未提交 badcase 的）
7. **GET** `/conflicts/{id}` → 查详情
8. **POST** `/{id}/badcase` → 提交工单（重复提交会返回 A0447）
